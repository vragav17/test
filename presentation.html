The need

Four people need this answer

Archive

Is this a version we already hold? Storing the same cut twice is expensive. Losing a unique one is worse.

Compliance

A cut was ordered for a territory. Did the supplier make it — and only it?

Localisation

Every change to the picture invalidates subtitles and dubs downstream. Which ones moved?

QC

A new master arrived. Is the difference editorial, or did something break in the transcode?

Today this is a person scrubbing two timelines side by side. It takes hours, it is done under deadline, and it is the first task dropped when the deadline wins.

So a tool only helps if its output can be trusted without re-checking it by hand. That one requirement shapes every decision in the rest of this deck.

Board · the judged component

Needleman-Wunsch, cell by cell

The one optimisation

A sequential-looking recurrence that is not

The left-neighbour term depends on the cell beside it:

H[i][j] = max(…, H[i][j-1] + gap)

Inherently serial — unless the gap penalty is linear.

Substitute G[j] = H[i][j] − j·gap:

G[j] = max(best[j] − j·gap, G[j-1]) = np.maximum.accumulate(…)

Three vector operations per row, not an inner loop.

A feature-length pair aligns in seconds, on a laptop, in pure numpy. No bioinformatics library, no heuristic, and no model anywhere near it — align.py contains zero references to one, verifiable with a single grep.

The second signal

A deliberate boundary

Audio annotates the timeline. It never scores it.

The scoring function sees picture only:

def score_matrix(a_bits, b_bits): d = hamming_matrix(a_bits, b_bits) s = np.full(d.shape, MISMATCH_SCORE) s[d <= WEAK_MAX_DISTANCE] = WEAK_SCORE s[d <= MATCH_MAX_DISTANCE] = MATCH_SCORE return s

…and afterwards, over aligned pairs only:

if op.type == "equal" and ahash_distance > 16: op.type = "audio_changed"

A second pass over what the alignment already matched — not a second term inside it.

An audio term inside the scoring function would make the alignment's behaviour a matter of tuning two weights against each other. The alignment is the part that has to be defensible, so nothing else is allowed to move it. A corrupt audio track can annotate wrongly; it can never corrupt the structure.

Three reasons the boundary sits there

Detection is arithmetic. Description is prose.

Reproducible

The same two files give the same regions — run to run, machine to machine, today and next year. No sampling, no temperature, no drift.

Auditable

A disputed result traces to a Hamming distance and a scoring rule you can read in twenty lines. Not to a token that happened to be sampled.

Honest about failure

A wrong description is obvious beside its own thumbnails. A wrong timecode would be undetectable — so the model never produces one.

The build order made this concrete: stages 0–5 and 7 had to work with the model disabled before stage 6 was written at all.

What real formats taught us

Three bugs that only genuine delivery files could find.

Board · bug 01

Five of six audio tracks silently vanished

Board · bug 02

Every shot faked a replace

Bug 03 · the subtle one

A fixed pipeline, still producing broken output

The trap

Both fixes above change how a proxy is built. A proxy cached from before the fix is still a perfectly valid file, so it was reused — and the bug survived its own fix, invisibly, on every machine that had run the tool.

The fix

PROXY_PIPELINE_VERSION is part of the cache key. Bump it and every stale proxy is rebuilt. The general lesson: a cache keyed on inputs alone is wrong the moment the transform can change.

And one that cut the other way. The leading theory for the audio problem was double-lossy encoding. Measured, it cost 0.4 dB — nothing. It was not the cause, and saying so was more useful than claiming the credit.

That is the habit the whole project runs on: form the hypothesis, measure it, and report the measurement even when it contradicts you.

What this proof of concept does not do

Colour is invisible

phash is greyscale by construction. A re-grade measures 0/64. The tool reports "no change" and is confidently wrong.

Two versions only

No fingerprint database, no library-wide dedup, no three-way compare. Deliberately out of scope.

Synthetic fixtures

Every fixture is generated, MXF and HDR included. Real footage — dissolves, handheld, fast cutting — is unmeasured.

One frame per shot

A change inside a long take, away from its midpoint, can be missed entirely.

None of these is a surprise or a defect — they follow from choosing a working end-to-end path over completeness. They are written down because a tool that hides its blind spots is more dangerous than one that has none.
